# Поставщик в двух измерениях: бренд и контрагент (2026-09-04)

## Суть проблемы
Дашборд всегда показывал поставщика в терминах МАТРИЦЫ (бренд: «Сигарети_PM»), а
контрагента по документам («ДЛ Солюшн») в нём не существовало вовсе. Владелец: «фактически
их возит по документам ДЛ Солюшн, которого вообще нет в списке».

Это НЕ разное написание одного имени. Замеры на живых данных:
- «ДЛ Солюшн» = 83,3 млн ₴ закупок, 229 штрих-кодов, шесть брендов: Сигарети_PM 32,9 млн,
  _BAT 23,2, _JTI 15,4, _IT 9,1, Нікотинові Паучі 2,4, Сигарети 0,16.
- Обратное тоже есть: «Оболонь» приезжает от 3 контрагентов, «Корона» от 5,
  «Волошкове Поле» от 4.
Связь многие-ко-многим и сшивается ПО ШТРИХ-КОДУ, а не по имени (так уже было
в `fetch_incoming.py`: сначала `m.sup` по barcode, затем `supplier_mapping` по имени).

## Где суммы сходятся, а где принципиально нет
- Закупки по контрагенту — точны на 100%: в накладной контрагент один. 253,6 млн ₴, 127 контрагентов.
- Закупки по бренду — 97,4% размечено, «(нет в матрице)» 1,92 млн ₴ (0,8%).
- **Продажи по контрагенту не аддитивны**: в чеке накладной нет. Из 304,7 млн ₴ выручки
  227,6 млн (74,7%) на позициях с ОДНИМ контрагентом, **60,5 млн (19,9%, 552 штрих-кода)
  на позициях, которые везут двое и больше**, 16,5 млн (5,4%) вообще без приходов 2026.
  Прямое приписывание дало бы задвоение на 20%.

## Решение
`fetch_incoming.py` отдаёт три ключа:
- `in_ts_month` — закупки по контрагенту помесячно (точно).
- `sales_ts_month` — продажи по контрагенту, РАЗНЕСЁННЫЕ пропорционально доле закупок
  контрагента по тому же штрих-коду. Плюс колонка `rev_exact` — часть строки, посчитанная
  без разнесения. Позиции без приходов уходят строкой «(нет прихода в 2026)».
  Проверено: сумма 304 669 095 против итога продаж 304 669 070 (разница 25 ₴ — округление),
  80% суммы «точные».
- `sup_bridge` — мостик контрагент<->бренд по штрих-кодам (198 строк): amt, skus.
  Он же рабочий список на дозаполнение `supplier_mapping`.

Фронт: карточка «Поставщики» на «Обзоре» (`ov_sup_card`) с двумя переключателями —
Имя: бренд/контрагент, Показатель: продажи/закупки. Это же закрыло вторую просьбу
владельца — разрез по приходам на главной. Клик по бренду ставит фильтр по нему,
клик по контрагенту — по ВСЕМ его брендам (`supBrands()` из мостика).
Бейдж «магазин не применяется» при фильтре точки: разреза по магазинам у приходов нет.

## Тесты (`supplierSuite` в check_dashboard.js, 82 -> 89 проверок)
Дословное требование владельца — «суммы не должны теряться и обрезаться», поэтому
проверяется именно равенство итогам: продажи по контрагентам == D.kpi.revenue;
закупки по контрагентам == закупки по брендам; мостик == сумме закупок; нет отрицательных
строк; доля точных строго между 0 и 100%; строка «нет прихода» существует; все четыре
комбинации переключателей рендерятся непустыми.

## Полнота матрицы — отдельная тема, замеры сделаны

- 285,7 млн (93,8%), 2011 штрих-кодов — В МАТРИЦЕ;
- **10,0 млн (3,3%), 612 штрих-кодов — закупается и продаётся сейчас, но в матрице НЕТ**
  (новинки, которые надо завести). Топ: Кроненбург 1664 673 тыс, Терея Саммер 542 тыс,
  Бонд Стрит Блю 504 тыс, Хітс Сільвер 293 тыс. По контрагентам: ДЛ Солюшн 3,43 млн
  (37 позиций), БІР 1,21 млн (23), Авангард 447 тыс (16);
- 3,55 млн (1,2%), 755 — распродаётся остаток (выведено);
- 3,32 млн (1,1%), 579 — закупалось, продажи затихли;
- 2,05 млн (0,7%), 365 — нет приходов вовсе (собственное производство / весовое).
Отчёт «Вне матрицы» с этими четырьмя группами и выгрузкой в Excel НЕ сделан — вариант Б,
владелец отложил. Он даст готовый список на ведение матрицы.
