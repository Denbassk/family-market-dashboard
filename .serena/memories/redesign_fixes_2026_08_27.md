## ЗАГАДКА ЗАКУПОК ВОДКИ — РЕШЕНА (это была НЕ ошибка интерфейса)
Симптом: продажи «Водки» 14,82 млн ₴, закупки 284 тыс ₴, в отчёте 3 строки вместо 91.
Причина: в `fetch_incoming.py` стоял фильтр `store IN keep` (38 торговых точек).
**Сеть закупается ЦЕНТРАЛИЗОВАННО через «Полевая-Склад»**, оттуда товар расходится по точкам.
Замеры на живом BigQuery 2026-08-27:
- `incoming_transactions` 2026: всего **246 036 600 ₴**, в 38 точках 180 873 232 ₴,
  вне точек **65 163 369 ₴ (26,5%)** — из них «Полевая-Склад» 63 917 303, «Производство»
  1 053 062, «Склад» 193 004.
- ВОДКА: всего 11 505 820 ₴, из них на склад 11 221 577 (97,5%), в точки 284 243.
  Все крупные поставщики («Баядера», «Трейдінг Продакт Компані», «Глобал-Сервіс (Алкоголь)»)
  везут 100% на склад.
- Эталон `torgsoft_incoming_ref_2026`: все объекты 249 362 693 ₴, только keep 183 338 885 ₴.
- Категории, где терялось больше всего: Водка 2,5% остаётся, Бренди/Коньяк 0%,
  Вяленое мясо 33%, Шоколад 45%, Печенье 53%. Табак 87%, Пиво 96% — те идут прямо в точки.

**ЗАДВОЕНИЯ НЕТ, проверено:** внутренних перемещений в `incoming_transactions` практически
нет (поставщик «Магазин» — 7,7 тыс ₴ за год), а закупки по всем объектам (246,0 млн)
сходятся с себестоимостью продаж 2026 (243,5 млн) = **101,0%**.

Правка: в `fetch_incoming.py` снят `store IN keep`, `store` нормализуется через
`domain.sql_case_full()` (склад сохраняет своё имя). `in_store_month` из эталона — тоже
все объекты, иначе сумма по точкам не сойдётся с итогом по категориям.
Результат: закупки 181 → 246 млн (+36%), «Водка» 284 тыс → 11,5 млн, «Бренди» 0 → 5,87 млн,
`in_prod_month` 8 467 → 15 229 строк, `full_data.json` 8,46 → 9,25 МБ (+810 КБ).
Диагностика в скрипте теперь сравнивает like-with-like: 246,0 против эталона 249,4 = −1,33%
(документированная разница «позиции против накладных»).

ВАЖНО про эталон (подтвердил собственник): в `torgsoft_incoming_ref_2026` НЕТ штрих-кодов,
только контрагент + сумма + центр учёта. Поэтому разрезы по категориям/товарам/поставщикам
берутся ТОЛЬКО из staging `_dash_in26` (уровень позиций), а эталон годится для итогов
и разреза по объектам. Так и сделано.

## Шесть поломок интерфейса — причины и правки
1. **Тепловая карта пустая.** `overrideHeatmap()` в redesign.js читал `window.D`/`window.S`,
   а `D`/`S` объявлены через `let`/`const` и свойствами `window` НЕ становятся
   (`typeof D`='object', `typeof window.D`='undefined'). Выходил на первой строке всегда.
   Переведён на `rdGetD()`/`rdGetS()`. В файле был неверный комментарий «доступен и через
   window.D» — исправлен.
2. **Мультиселект «залипал»** («Все поставщиков (4)» при пустых фильтрах). Чекбоксы были
   ни при чём. В ПЯТИ местах звался `msSync(один_ключ)` вместо `msSyncAll()`: `setFilter`
   (клик по графику), `toggleOwnProd`, крестик на чипе, «сбросить срез», клик по ABC-карточке.
   Каскад категория↔поставщик пересчитывал список, а соседнюю кнопку никто не обновлял.
3. **Аналитика игнорировала магазин и месяц** — МОЯ регрессия из ревизии вкладок: снёс
   «Разрез», а ABC/Парето/скаттер/покрытие никогда не фильтровались. Теперь ABC считается
   из `workProducts()` (новая `abcNow()`), скаттер — из `catAgg()`, оборачиваемость по
   магазинам сужается по `S.store`, `coverage()` показывает только выбранные точки и считает
   доли от их суммы. Решение собственника: «всё в разрезе фильтра».
4. **Проценты +3,3% на карточках не пересчитывались** — redesign считал их из `D.monthly`
   (вся сеть). Основной скрипт теперь кладёт помесячный ряд среза в глобал `OV_SERIES`
   (заполняется в `renderOverview`), redesign берёт его через `rdGetGlobal('OV_SERIES')`.
5. **«Оборот, дн» завышен в 8 раз** (см. `mem:features_plan`). Добавлены `monthsCount()`,
   `turnsPeriod()`, `shelfDays()`. Было 160 дн у Іскринський 19В, стало ~20; максимум по
   сети 68 дн. Подпись под графиками переписана.
6. **Отчёт «Закупки» молчал о неполноте.** В подзаголовок добавлено «закупки = X% от продаж
   этого среза», красным при <25%. После правки пайплайна по «Водке» 77,6%, по «Пиву» 86,6%.

## Мины на будущее
- `D` и `S` НЕ на `window`. В redesign.js для доступа к ним есть `rdGetD()`/`rdGetS()`
  (индирект-eval). Любой новый код в слое редизайна обязан ходить через них.
- Любая смена фильтра должна звать `msSyncAll()`, а не `msSync(ключ)` — из-за каскада.
- `redesign.js` целиком обёрнут в IIFE, экспортирует наружу только `window.RD` (27 функций)
  и оборачивает `window.render` + подменяет `window.chart` для `ov_cat`/`ov_store` (заглушка,
  вместо ECharts рисуются SVG-рейтинги). Столкновений имён с основным скриптом НЕТ.
- `tests/truth.json` протухает за дни: 4 «провала» вида «== BigQuery» = устаревший эталон,
  лечится `python tests/truth.py`.
