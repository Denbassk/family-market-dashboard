# Доменные правила

## Нормализация магазинов (NORM dict в fetch_data.py / fetch_page3.py)
- «Полевая 83» (янв–март) + «Полевая-Магазин» (апр+) → мержатся в единый **«Полевая магазин»**.
- «Полевая-Склад», «Полевая-Просрок» (просрочка) — ИСКЛЮЧАЮТСЯ из keep, не мержить.
- `keep` — список включённых магазинов; `cs_tt`/`cs_sc` — CASE-нормализация по колонке store/store_address.

## ОПТ и средний чек (важно, 2026-08-20)
`WHOLESALE = ["Полевая магазин"]` в fetch_data.py -> ключ `wholesale_stores` в full_data.json.
Это опт/склад: по эталону продаж Торгсофт зовёт тот же объект «Полевая-Склад» с `is_warehouse=true`
(январь: суммы и число чеков совпадают до документа с «Полевая 83» из turnover_transactions).
Замер за 2026: 38 514 767 ₴ выручки и 29 809 чеков — **13,4% выручки при 1,7% чеков**,
средний чек 1292 ₴ против розничной медианы 145 ₴ (мин 98 Тракторобудівників 95, макс 181 Іскринський 19В).
Сетевой средний чек из-за неё был завышен на **13,5% (166 вместо 147 ₴)**, и разрыв рос:
+7% в марте -> +19% в мае–июле.
Правило: ВЫРУЧКА и ЧИСЛО ЧЕКОВ остаются полными (это реальные продажи сети), отдельно
пересчитывается только СРЕДНИЙ ЧЕК — по рознице, с подписью «без опта».
Фронт: `wholesaleSet()` + `avgCheck(k)` (рядом с блоком возвратов). Если выбран ТОЛЬКО оптовый
магазин — показывается его собственный чек с подписью «опт». В таблице «Магазины» строка помечена
«(опт)», сводный «Средний чек ₴» тоже без опта, а Ср.чек в самой строке — свой, как есть.
Фолбэк `['Полевая магазин']` в JS, чтобы работало и до пересборки данных.

## Категории — ТОЛЬКО из матрицы (assortment_matrix_full)
turnover_monthly имеет «грязные» категории — не использовать. Матрица = источник истины.
Override в staging по префиксам названия: 'Кулінарія'→'Кулинария', 'Випічка'→'Выпечка',
'Хот-Дог'→'Хот-дог'. Нет в матрице → 'Прочее (нет в матрице)' / поставщик '(нет в матрице)'.
С 2026-08 категория/поставщик едины НА НАЗВАНИЕ товара (два штрих-кода одного товара больше
не разъезжаются по разным категориям) — см. `mem:crossfilters_and_cubes`.

## Две таксономии поставщиков
Матрица = БРЕНД («Оболонь», «Сигарети_PM»), Торгсофт = КОНТРАГЕНТ («Союз (Оболонь)», «ДЛ Солюшн»).
Перевод: barcode -> матрица, затем `supplier_mapping.matrix_supplier`. См. `mem:feature_returns`.

## Технические товары (расходники собств. производства)
Не пробиваются на кассе поштучно (кофейный аппарат, хот-дог, упаковка) → в отчёте «не двигается»
ложно висят как «нет продаж». Классификатор `is_tech()` в `scripts/fetch_stale.py` И зеркально
в JS (`isTech()`, константа `TECH_SUB` в index.html) — ОБЯЗАТЕЛЬНО держать синхронными.
Логика: список однозначных подстрок (кава зернова, стакан паперов/пластик, кришка,
капучино/сухе молоко/какао «(1кг)», булка для хот, …) + компаунд-правило:
('сосиск'|'сардель') И ('1кг'|'мк '). Даёт ~36 SKU / ~454 строки.
Чекбокс «скрыть технические» (fOff → S.noOff) фильтрует по этому флагу на всех вкладках.

## Кулинария/выпечка
Собственное производство, вне матрицы. Ищется по префиксам «Кулінарія»/«Випічка».
Хот-дог штрих-коды: 2984670043865, 2984670043889, 2984670043872, 2984670060169.

## Приходы vs эталон
Магазины закупок — из REF (torgsoft_incoming_ref_2026, уровень накладных, без задвоений).
ПОСТАВЩИКИ закупок с 2026-08 — из staging `_dash_in26` (уровень позиций): мультибрендовый
контрагент на уровне накладной неразделим. Категории/товары приходов — тоже из staging.

## Выручка считается по ПРЕЙСКУРАНТУ
`price_retail` в turnover_transactions — цена до скидки. Скидки за Q1 = 357 604 ₴ (0,37%),
их знает только `torgsoft_sales_ref.amount`. См. `mem:reconciliation`.
