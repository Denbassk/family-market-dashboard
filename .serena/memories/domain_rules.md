# Доменные правила

## Нормализация магазинов (NORM dict в fetch_data.py / fetch_page3.py)
- «Полевая 83» (янв–март) + «Полевая-Магазин» (апр+) → мержатся в единый **«Полевая магазин»** (это опт/склад, помечен как таковой).
- «Полевая-Склад», «Полевая-Просрок» (просрочка) — ИСКЛЮЧАЮТСЯ, не мержить.
- `keep` — список включённых магазинов; `cs_tt`/`cs_sc` — CASE-нормализация по колонке store/store_address.

## Категории — ТОЛЬКО из матрицы (assortment_matrix_full)
turnover_monthly имеет «грязные» категории — не использовать. Матрица = источник истины.
Override в staging по префиксам названия: 'Кулінарія'→'Кулинария', 'Випічка'→'Выпечка', 'Хот-Дог'→'Хот-дог'. Нет в матрице → 'Прочее (нет в матрице)' / поставщик '(нет в матрице)'.

## Технические товары (расходники собств. производства)
Не пробиваются на кассе поштучно (кофейный аппарат, хот-дог, упаковка) → в отчёте «не двигается» ложно висят как «нет продаж». Классификатор `is_tech()` в `scripts/fetch_stale.py` И зеркально в JS (`isTech()`, константа `TECH_SUB` в index.html) — ОБЯЗАТЕЛЬНО держать синхронными.
Логика: список однозначных подстрок (кава зернова, стакан паперов/пластик, кришка, капучино/сухе молоко/какао «(1кг)», булка для хот, …) + компаунд-правило: ('сосиск'|'сардель') И ('1кг'|'мк '). Даёт ~36 SKU / ~454 строки. НЕ ловит розничные вафли-трубочки, чипсы-бекон, йогурт-стакан, сигареты, конфеты.
Чекбокс «скрыть технические» (fOff → S.noOff) фильтрует по этому флагу на всех вкладках.

## Кулинария/выпечка
Собственное производство, вне матрицы. Ищется по префиксам «Кулінарія»/«Випічка». Хот-дог штрих-коды: 2984670043865, 2984670043889, 2984670043872, 2984670060169.

## Приходы vs эталон
Магазины/поставщики закупок — из REF (torgsoft_incoming_ref_2026, уровень накладных, без задвоений). Категории/товары приходов — из staging _dash_in26 (в REF нет barcode). Ранее выявлено 376 «потерянных» накладных (~595К ₴).
