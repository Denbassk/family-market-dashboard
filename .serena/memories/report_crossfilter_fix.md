# Отчёты игнорировали кросс-фильтр и молча врали (2026-09-17)

## Что нашлось
Владелец хотел посмотреть, какие магазины больше всего продают хот-догов, и не нашёл
такого разреза. Разрез там был — сломан был фильтр:

- группировка **«Магазины» + фильтр категории «Хот-дог»** -> **304 669 070 ₴** (вся сеть)
  вместо 619 584 ₴. То есть под заголовком одной категории показывались все продажи сети.
- группировка **«Категории» + фильтр магазина** -> 304,7 млн вместо 10,9 млн по точке.
- то же для «Поставщики» + фильтр магазина.

Причина в `reportPivot()`: источники строк одномерные (`store_month`, `cat_month`,
`supplier_month`), и каждая ветка фильтровала ТОЛЬКО по своему измерению
(`dim==='store'` -> фильтр по S.store и всё). Фильтр другого измерения просто не
применялся, без единой пометки. Это опаснее, чем «разреза нет»: цифра выглядит
законной.

## Починка
Добавлен `rpCube(dim, months)` — читает кубы пар `store_cat_month` / `store_sup_month`
(появились 2026-09-03, `mem:kpi_trends_and_month_compare`) и строит строки отчёта точно:
- «Магазины» + категория/поставщик;
- «Категории» + магазин;
- «Поставщики» + магазин.
Куб не применяется, когда включены ABC, поиск по названию, «скрыть технические» или
выбран источник «Закупки» — там ветки остались прежние, но теперь ставят честную
пометку RP_NOTE вместо молчания. Для трёх измерений сразу (магазин+категория+поставщик)
куба нет: применяются два, третье названо в пометке.

Проверка после: «Хот-дог» по магазинам — 619 618 ₴ на 27 точках (эталон 619 584,
расхождение 34 ₴ — округление в кубе). Топ: Салтівське шосе 264В 110 075,
Ньютона 111 78 165, Шевченко 341 59 830.

## Тесты
`reportSuite()` в `tests/check_dashboard.js` (93 -> 96 проверок): сумма отчёта под каждой
из трёх комбинаций равна независимому эталону (`by_category` / `kpiNow()`).

## Чего ещё нет
Настоящей двумерной сводки «строки = товары, колонки = магазины» в отчёте по-прежнему
нет. Для продаж она возможна из куба `prod_store` (годовые суммы, без месяцев) —
это следующий шаг, если владелец попросит. Для закупок разреза «товар × магазин»
в данных нет вообще.
