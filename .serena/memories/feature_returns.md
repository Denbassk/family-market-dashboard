# Возвраты поставщикам (фаза 1, 2026-08)

## Источники и почему так
- Позиции: `family_market.outgoing_to_supplier_transactions` (barcode/qty/суммы, 2025-01…2026-07, 44 290 строк).
- Эталон-контроль: `family_market.torgsoft_outgoing_ref` (уровень документа, только 2026, 8 205 строк).
  Сверка по doc_number за 2026: совпало 7 224 док., расхождение по ним 4 779 ₴; только в tx 24 док. (82,9 тыс),
  только в ref 12 (29,1 тыс). Итог: 3 407 242 vs 3 348 659 = +1,75%.
- В ref есть doc_date/store/supplier/is_prosrok — эталон богаче, чем считалось («только поставщик+сумма» — неверно).

## Поставщик: две таксономии
Торгсофт пишет КОНТРАГЕНТА («Союз (Оболонь)», «ДЛ Солюшн»), матрица — БРЕНД («Оболонь», «Сигарети_PM»).
48 из 52 имён возвратов и 112 из 128 имён приходов в матрице отсутствуют.
Перевод: **сначала barcode -> assortment_matrix_full.supplier, затем supplier_mapping.matrix_supplier**.
Именно в таком порядке: `supplier_mapping` для мультибрендового «ДЛ Солюшн» даёт одно случайное имя
(в таблице 6 вариантов), а по barcode 67 млн ₴ корректно раскладываются на Сигарети_PM/BAT/JTI/IT.
Согласованность двух способов на возвратах: 14 535 совпадений против 11 расхождений.
Таблицы-помощники в BQ (раньше не использовались): `supplier_mapping` (156 строк), `supplier_aliases`,
`supplier_mapping_matrix` (matrix_supplier -> conditions_supplier), `supplier_conditions` (returns_allowed/percent/text).

## Физобмен
Признака в данных НЕТ: встречные «бесплатные» приходы от поставщиков отсутствуют (все 1745 нулевых
строк — от служебного «Магазин»), `is_prosrok` = просто «магазин называется *-Просрок»,
`supplier_conditions.returns_text` заполнен вручную (подсказка «частично обмен» только у УДК).
Поэтому список ведётся руками: `scripts/returns_config.py` -> `EXCHANGE_SUPPLIERS` / `EXCHANGE_PAIRS`
(имена канонические, как в матрице). Флаг едет в куб полем `x`, фронт рисует «в т.ч. обмен».

## Классы точек (ползунок охвата на «Обзоре»)
- `retail` 1 664 278 ₴ — 38 точек сети (совпадает с NORM/keep).
- `prosrok` 562 255 ₴ — «Магазины-Просрок», «Полевая-Просрок». ВАЖНО: это сводные служебные точки,
  привязки к конкретному магазину нет -> при выборе магазина просрочка не показывается (написано в подсказке).
- `wh` 1 180 709 ₴ — «Полевая-Склад», «Производство», закрытая «Професорська 12».
Ползунок `S.retScope`: 'r' | 'rp' (по умолчанию) | 'all'; выбор в localStorage `fm_ret_scope`.

## Формат данных
`scripts/fetch_returns.py` -> ключи в full_data.json:
- `returns_fact` — куб 4 473 строки: `[мес, s_i, c_i, p_i, k_i, закуп, розница, кол-во, строк, (1=обмен)]`
- `returns_dim` — `{s:[…],c:[…],p:[…],k:['retail','prosrok','wh']}`
- `returns_docs`, `returns_ref`, `returns_terms` (условия возврата по поставщику), `returns_meta`
Размер +169 КБ. Куб маленький -> любой срез точный, кросс-фильтры месяц×магазин×категория×поставщик работают.
Подключено в `build_data.py` шагом 2c-bis.

## Фронт
`returnsNow()` / `retRows()` / `retTerms()` рядом с `workProducts()`; 8-я KPI-карточка «Возвраты ₴»
(значение — закупочная сумма, подпись — % от выручки в розничных ценах + охват + обмен);
таблица `ov_ret` (поставщик / закуп / доля / розница / кол-во / условия), клик = setFilter('sup').
CSS-класс `.seg` — сегментный ползунок.
