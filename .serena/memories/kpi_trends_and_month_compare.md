# Тренды на KPI и сравнение любых двух месяцев (2026-09-03)

## Что было
Спарклайн и стрелка жили только на «Обзоре», на карточках №0 и №1 контейнера `#ov_kpis`
(жёсткие индексы в `redesign.js`), ряд брался по ОДНОМУ измерению с приоритетом
категория -> поставщик -> магазин, стрелка всегда «последний месяц против предыдущего».
При «Пиво + Байрона 156» спарклайн показывал «Пиво» по всей сети, а число в карточке —
по срезу.

## Данные: два куба пар (решение владельца — точность важнее +1,3 МБ)
`fetch_data.py` отдаёт `store_cat_month` (22 306 строк) и `store_sup_month` (25 365).
Формат строки: `[мес, индекс магазина, индекс категории/поставщика, выручка, прибыль,
кол-во, чеки, SKU]`. Индексы — в `out["stores"]` и в списки `scm_cats` / `ssm_sups`.
Чеки берутся из витрины `_dash_r26`: в GROUPING SETS добавлены разрезы
`(store, category, mo)` и `(store, supplier, mo)` — тот же скан, ноль дополнительной цены.
`full_data.json` 9,8 -> 11,1 МБ (gzip прибавит ~0,3 МБ).

## ПОБОЧНЫЙ ЭФФЕКТ, ради которого стоило: `kpiNow()` стал точным на паре фильтров
Комбинация магазин + категория (и магазин + поставщик), в том числе с месяцем, раньше
уходила в `workProducts()`, где связка месяц x магазин считается разнесением ГОДОВОГО куба
по доле месяца — оценка. Замер: январь, одна точка, одна категория — оценка 129 042 ₴
против точных 152 832 ₴ (расхождение 18%). Теперь в `kpiNow()` есть ветка по кубам.
Это закрывает часть давней мины «≈ оценка (месяц x магазин)».

## Фронт
- `sliceSeries()` — помесячный ряд текущего среза. Источник по приоритету:
  магазин+категория -> `store_cat_month`; магазин+поставщик -> `store_sup_month`;
  дальше одиночные `cat_month` / `supplier_month` / `store_month` / `monthly`.
- `buildTrend()` вызывается в начале `render()` и кладёт `window.KPI_TREND`
  = {months, series{metric->{mo:value}}, cmp:{a,b}, partial, src, approx, soft, note}.
  Метрики: revenue, gp, qty, receipts, skus, margin, avgcheck.
- `kpiCards(el, arr)` принимает 4-й элемент строки — КЛЮЧ МЕТРИКИ, кладёт его в
  `data-metric`. Больше никаких индексов карточек.
- `redesign.js: addSparklines()` переписан: обходит `.kpi[data-metric]` во всём документе
  (любая вкладка), берёт ряд по ключу, рисует спарклайн и стрелку по паре из `cmp`,
  в `title` — «Май 231 тыс против Мар 184 тыс». Вызывается после КАЖДОГО `render()`.
- Селектор «Сравнить с» в глобальной панели (`#fCmp`), `S.cmp` = 'prev' | номер месяца.
  A = выбранный месяц (или последний полный), B = `S.cmp`.

## Что НЕ получает тренд и почему
- «Заморожено в неликвидах», «Дефицит», «Остатки на» — считаются от ОДНОГО снимка склада;
  в `stock_matrix` всего три даты. Тренд появится, только если копить снимки.
- Чеки, SKU и средний чек при выборе НЕСКОЛЬКИХ категорий/поставщиков: не складываются
  (один чек лежит в нескольких категориях). Спарклайн рисуется, стрелка гасится,
  в `title` объяснение.
- ABC, поиск по названию, «скрыть технические» — помесячных рядов под них нет вообще.
  Стрелка гасится целиком (`cmp: null`), спарклайн остаётся как форма динамики.
- Если данные собраны ПРЕЖНИМ скриптом (кубов нет), пара фильтров падает на одно
  измерение — стрелка тоже гасится, в note «нужна пересборка данных».
- «Отчёты»: тренд на «Итого» только при источнике «Продажи»; у закупок свой период.

## Тесты
`trendSuite()` в `tests/check_dashboard.js` (71 -> 82 проверки). Главный инвариант:
для пяти комбинаций фильтров ряд `sliceSeries()` помесячно СОВПАДАЕТ с `kpiNow()` за тот
же месяц. Плюс проверки пары сравнения (prev, явный месяц, гашение на ABC) и разметки
`data-metric`.
