**Первым делом (обязательно, до любых правок):**
1. Активируй проект Serena: он называется `deploy_full` (путь тот же). Прочитай ВСЕ его memory-файлы: `project_overview`, `data_pipeline`, `deployment_and_ops`, `domain_rules`, `frontend_dashboard`, `frontend_filters`, `frontend_current`, `feature_stores_heatmap`, `open_tasks`. Там вся архитектура, доменные правила, воркфлоу деплоя, источники данных и открытые задачи.
2. Прочитай `docs/COWORK_TASK.md` (ревью по миграции остатков).
3. Схемы BigQuery и данные проверяй сам через SA-ключ в `credentials/*.json` (env GOOGLE_APPLICATION_CREDENTIALS). Не доверяй именам колонок на память — используй `get_table().schema`.

**Как устроено кратко** (детали — в памяти): статический `docs/index.html` (ECharts + ExcelJS, ванильный JS, без React), данные `docs/full_data.json` (+ отдельный `docs/stale.json`), сбор — `scripts/build_data.py` (гоняет sync_matrix → fetch_data → fetch_page3 → fetch_matrix → fetch_incoming → fetch_stale) из BigQuery. Остатки — из снимка `stock_matrix` (НЕ из удалённой stock_current, НЕ из turnover_monthly). Матрица синхронизируется из Google-листа скриптом `sync_matrix.py`. Пуш и запуск обновления делаю Я на своей машине из PowerShell — ты готовишь код и даёшь команды/тестируешь в песочнице.

**Задачи (по приоритету):**

1. **Возвраты на вкладке «Обзор».** Добавь карточку с общей суммой ВОЗВРАТОВ, которая корректно фильтруется по поставщику (и по возможности по остальным срезам). 

2. **Сверка с эталонами — цифры расходятся.** Я добавил в BigQuery эталонные таблицы (проверь точные датасет/схему сам):
   - `torgsoft_outgoing_ref` — эталон ВОЗВРАТОВ (только поставщик+сумма).
   - `torgsoft_sales_ref` — эталон ПРОДАЖ по чекам (только поставщик+сумма, НЕ до конца загружен данными — учитывай неполноту).
   - `outgoing_to_supplier_transactions` — ВОЗВРАТЫ с разрезом по позициям.
   - `torgsoft_incoming_ref_2026` — эталон ПРИХОДОВ (уже частично используется).
   Продажи по чекам не сходятся с эталоном. Нужно свериться и замапить наши агрегаты с эталонами по трём потокам: приходы, возвраты, продажи. Эталоны без позиционного разреза (кроме outgoing_to_supplier_transactions) — годятся для главной страницы и сверки сумм, но не для детализации.

3. **Свежий взгляд на структуру.** Проанализируй архитектуру проекта (пайплайн, index.html, источники данных, фильтры) и укажи недочёты + предложи правки. Сначала покажи разбор и план — я утвержу, потом правим.

**Отложенные фичи** (можно после первых трёх): GMROI в «Магазины»; ценовые сегменты в «Позиции» (диапазоны цен → выручка/прибыль/маржа и доли); корзинная аналитика в «Позиции» (структура корзин, категории в чеке, одиночные покупки — «комбинации товаров»/cross уже есть); перепроверка кросс-фильтров на всех вкладках.
