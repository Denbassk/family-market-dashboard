# Обновление данных дашборда

## Порядок (снизу вверх: сначала БД, потом JSON, потом git)

### 1. Выгрузить остатки из Торгсофта
Отчёт "Наличие товаров в торговой сети" (длинный формат: строка = товар + магазин).
Сохранить в папку reports_stock под именем с датой, например:
`reports_stock\Остатки на складах на 11.08.2026.xlsx`
Обязательные колонки: Штрих-код, Товар, Магазин, Кол-во, Цена розничная, Себестоимость.

### 2. Загрузить снимок в BigQuery
```powershell
python scripts\load_stock.py
```
Пишет в `family-market-analytics.family_market.stock_matrix` (поле snapshot_date).
Идемпотентно: повторный запуск за ту же дату сначала удаляет старые строки.
Без этого шага дашборд покажет вчерашние остатки.

### 3. Пересобрать JSON
```powershell
$env:PYTHONUTF8='1'
python scripts\fetch_stale.py   # docs\stale.json  - вкладка "Товары без движения"
python scripts\fetch_data.py    # docs\full_data.json - все остальные вкладки
```

### 4. Отправить в git
```powershell
git add docs/stale.json docs/full_data.json
git commit -m "data update"
git pull --no-rebase
git push
```
Сайт переразвернётся за 1-2 минуты. В браузере обновить страницу через Ctrl+F5.

## Что проверить после обновления
Дата "Данные на" в KPI = дата снимка. Число позиций и сумма примерно на уровне
предыдущего дня (резкое падение = снимок загрузился не полностью).
Магазины "Полевая-Магазин" и "Полевая-Склад" присутствуют по отдельности,
старых названий (Полевая 83, Героїв Сталінграда) быть не должно.

## Кнопка "Обновить данные" на сайте
Запускает CI-пересборку JSON из BigQuery. Снимок Торгсофта она НЕ подтягивает:
шаги 1-2 всегда выполняются локально. Кнопка полезна, когда в BigQuery уже
приехали свежие продажи и приходы, а остатки менять не нужно.

## Известная проблема
Если `fetch_data.py` падает с "404 Not found: stock_current" - это ожидаемо:
таблица удалена, скрипт ещё не переведён на stock_matrix. См. docs\COWORK_TASK.md.
